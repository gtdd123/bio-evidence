# BioEvidence 项目原则

版本：0.1.0  
日期：2026-10-08（Asia/Shanghai）  
状态：用户已于 2026-10-08 确认；Spec 已于 2026-10-09 确认，当前进入 Plan 阶段  
依据：已确认的《科研平台需求摘要》

本文件规定长期适用的产品与工程原则。具体功能、接口、容量和版本范围由后续 Spec 与 Plan 定义，不能把原则文档视为实现已完成的证据。

## 1. 功能追溯到已确认的平台目标

**规则：** 每项功能须说明其科研用户价值、已确认的需求来源和可观察结果。研究课题作为平台使用场景；算法训练、GPU 调度等新业务不能从课题背景中隐含推导。范围发生实质变化时，先更新受影响的需求和验收约定。

**理由：** 平台需要持续服务不同课题，明确的功能边界能避免开发偏离用户目标。

**验证：** 评审每项任务与需求的对应关系，检查差异是否引入没有确认的新业务。新范围获得明确决策并同步文档后才可进入实现。

## 2. 服务端身份与资源授权决定访问权

**规则：** 个人空间默认私有，项目资源依成员关系授权。客户端提供的用户、工作区、项目或会话标识不能证明访问权。会话、证据、报告、资料文件、预览及事件订阅都须检查实际身份与资源关系；成员移除后不能继续获得后续内容。平台管理身份执行数据操作时也须遵守相应访问规则。

**理由：** 多人共用服务时，目录划分和界面隐藏不能防止越权。

**验证：** 通过服务端接口验证跨用户访问、伪造资源标识、移除成员、旧凭据和事件订阅；对允许及拒绝路径分别保留证据。授权规则变化须更新相应测试与 Spec。

## 3. 私有资料边界覆盖所有衍生内容与出口

**规则：** 私有实验资料只在用户或课题组控制的可信环境内处理。原文、图像、片段、摘要、上下文、缓存及包含私有内容的日志和产物继承其数据边界。模型、辅助调用、工具、分享和遥测都须遵守该边界；提示词、权限模式或客户端参数不能绕过检查。可信推理连接缺失或失效时拒绝执行，不能回落到外部云端。

**理由：** 文件留在服务器上，并不能保证其内容没有通过推理、分享或诊断请求外发。

**验证：** 用合成私有材料及可观测的模拟出口验证直接请求、混合公开/私有上下文、辅助调用、工具调用、公开分享和连接失效。禁止路径不得发出包含私有内容的请求。降低数据边界或改变可信环境必须有显式、可审计的决策并同步约定。

## 4. 研究结论保留可检查的证据链

**规则：** 文献事实须来自实际读取的来源，研究结论须关联证据。保留稳定论文标识、读取的来源层级和版本、原文片段及定位；模型推断、原文事实与用户修改分别记录。没有全文时标明基于摘要，缺失信息不补造，失效引用或未核对内容不能标为已验证。

**理由：** 科研人员需要复核结论，也需要知道当前证据的限制。

**验证：** 使用固定文献样例核对来源、片段和定位，验证摘要降级、缺失证据、重复标识、用户修订及引用失效。生成报告的引用须能回到其证据记录和实际读取的内容。

## 5. 多端复用同一业务核心与明确契约

**规则：** 身份、资源授权、会话、科研产物和执行状态由共享业务核心管理；桌面、Web 及其他入口通过明确契约访问。模型差异通过适配边界表达，不把同一业务规则分别写进各端。契约或持久化格式变化须说明兼容、迁移及失败行为。

**理由：** 用户切换入口时，需要继续同一份工作；不同客户端不能产生不同权限或证据含义。

**验证：** 运行契约检查和跨端场景，核对同一身份、会话、产物和状态；不支持的接口版本或模型能力须给出明确结果。评审新增逻辑是否重复核心规则。

## 6. 执行状态和持久化结果必须一致

**规则：** 长任务具有明确的进行、完成、失败和取消状态，关键结果与状态可持久化。不能将界面收到事件等同于结果已保存，也不能将历史记录存在等同于任务已恢复。恢复和重试须识别已完成步骤及副作用，避免并发执行体破坏同一会话或覆盖用户修改。

**理由：** 科研调研常耗时较长，中断、切端及重启后仍须知道哪些工作实际完成。

**验证：** 在关键步骤模拟取消、失败、进程重启及并发请求，核对状态、历史与产物；检查重试是否重复副作用。对不能自动恢复的步骤明确记录其状态与下一步。

## 7. 大型资料集按受控范围与资源预算访问

**规则：** 实验目录默认作为受控资料来源引用，访问限定于已注册的资料根目录和授权项目。浏览、检索、解析及预览须有明确的批次或资源上限；不因打开界面就无界递归扫描、读取全部原图或复制整个资料集。文件内容和派生预览遵守相同权限。

**理由：** 大量显微图像和连续帧需要可预测的资源使用，也不能借文件路径访问其他研究资料。

**验证：** 用可复现的大目录和文件样例检查按需读取、上限、预览、错误格式与权限；验证越界路径、符号链接及未注册目录的拒绝访问。复制或导出属于独立的明确操作，仍受数据边界约束。

## 8. 审计可解释，凭据和内容最小化留存

**规则：** 关键权限、配置、资料访问、执行、分享及产物变更记录操作者、资源、结果和时间。普通诊断默认保留必要标识及错误类型，不记录密钥、令牌、完整提示词或私有资料正文。凭据在可信后端管理，不能随客户端、示例、日志或仓库分发；审计记录也有访问边界。

**理由：** 平台既要能定位问题和追踪操作，也要避免诊断与交付本身成为资料泄露出口。

**验证：** 检查成功及失败日志、客户端构建、配置示例和待提交文件；验证审计覆盖关键操作且未泄露测试凭据或合成私有正文。需保留额外内容的诊断必须显式说明范围、访问者和留存方式。

## 9. 完成声明依据实际验证与可复现结果

**规则：** 行为交付必须有匹配风险的验证；核心身份、数据边界、证据和持久化规则使用可重复的自动检查。外部模型及服务可用确定性替身测试，但不能据此声称真实接口或实际服务器已验证。报告实际运行命令、结果、差异和未验证项；未完成的验证不得包装成成功。

**理由：** 求职展示与课题组试用都依赖可信的工程证据，不能只依靠界面截图或模型输出。

**验证：** 独立核对验证记录与实际输出，将模拟测试、真实接口验证、构建和跨端验收分开记录。失败或不可用的必要验证保留明确的修复或后续验证事项。

## 10. 保留上游来源，准确表达新增贡献

**规则：** 保留适用的许可证、NOTICE、署名和第三方要求，派生产品使用 BioEvidence 的名称与标识。公开说明可核实的上游版本或快照来源，分别列出继承能力与本项目新增工作；不能将未核实的上游提交或已有功能写成个人原创。公开交付只包含允许公开的代码、示例和文档。

**理由：** 公开二次开发需要明确来源，也需要让审阅者识别实际开发价值。

**验证：** 核对许可证、来源记录、品牌位置、贡献说明和待发布文件；检查实验原数据、凭据和个人简历没有进入提交。新增依赖或素材须记录来源及适用分发条件。

## 修订与适用

原则调整应说明原因、受影响的需求和接口、验证方式及迁移影响。现有源码不满足原则时，应记录差距并纳入后续任务，不能把既有行为视为例外。需求或实现计划不能静默覆盖本文件；实质原则变更需要用户确认。

本文件已确认。后续 Spec 定义具体行为与验收，Plan 定义技术方案，Tasks 定义实现与验证单元。当前文件不授权未确认的新业务，也不代表应用已实现或已发布。
